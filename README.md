# 模型助手 · DeepSeek Harness 插件

适配 DeepSeek Harness `0.2.1-rc.5`，通过 Cordis Slot 与宿主配置服务扩展界面，不修改应用安装包。macOS 已实测，Windows 待实机验证。

## Windows 快速安装

仓库已包含构建产物 `index.js` 与 `client.js`，无需自行编译源码。

1. 确认 Windows 上的 Harness 版本为 `0.2.1-rc.5`。
2. 在 Harness 打开「插件 → 添加插件」，粘贴以下仓库地址并安装，然后点击「立即启用」。

```text
https://github.com/qinghuan50/dsh-model-assistant.git
```

也可克隆仓库并执行 `npm ci`，再在同一输入框填写仓库本地绝对路径，例如 `C:\Projects\dsh-model-assistant`。本地目录安装后请保留该目录及其依赖。

安装后可验证：侧栏「模型助手」打开独立设置页；聊天框模型列表能刷新并显示真实容量、厂商和能力；未提供等级时为 `default`；切换模型后底部徽章同步；关闭功能恢复原生选择器。刷新与选模无需发送聊天消息。

本地目录重新构建后需重启 Harness，确保 Host 与 Client 都加载最新代码；仅更新前端文件可能仍使用内存中的旧后端。目录 RPC 保持兼容旧版；未重载后端时联网补全会提示重新加载，不会使目录刷新失败。已有同名插件时，按宿主提示卸载旧版再安装；需要保留的手填资料请先记录。反馈 Windows 问题时附上 Harness 版本、错误码及相关界面即可。

## 使用

- 侧栏「模型助手」打开独立设置页，设置「启用模型助手」与「在侧栏显示入口」两个开关。
- 宿主「设置 → 模型助手」也提供同一组设置，隐藏侧栏后仍能进入。
- 开启后点击聊天输入框的模型控件，搜索或按渠道、厂商、能力、上下文筛选，选择完整的渠道/模型路线。
- 关闭功能会撤销插件对模型控件的覆盖，恢复宿主原有控件。原有 `/model`、会话持久化、选模权限和推理等级继续由宿主处理。
- 底部只显示模型名、渠道与厂商徽章、已知能力，不重复上下文或倍率。
- 有实际声明的推理等级时，底部或展开列表均可切换；接口未返回等级时显示 `default`，表示使用提供商默认行为，不把字符串 `default` 作为推理参数发送。
- 模型选择器打开时读取目录；「刷新模型列表与资料」可强制绕过插件的五分钟接口缓存（宿主目录仍遵循其缓存策略）。请求失败会标明使用旧接口缓存或本地参考资料。

## 数据

渠道自动区分 **DeepSeek 官方**（账号、API Key）、**第三方**（宿主内置提供商）与 **自定义**（用户声明的渠道），非官方路线可在模型助手设置中修正分类，并按来源类型筛选。官方模型仅展示「官方」标识，不展示渠道或未知厂商徽章；筛选官方来源时隐藏渠道、厂商筛选项。分类来自适配器的 `declared` 标记，不根据显示名或 URL 猜测。DeepSeek 官方路线始终通过宿主读取目录并复用其认证与协议；不会套用通用 Bearer 认证或写入账号渠道不允许的 `models` 配置。

显式配置 API 地址且使用 OpenAI 兼容协议的第三方/自定义渠道从目录接口获取模型，支持标准 `data` 数组及增强 `models` 数组/字典。字典键保留为请求使用的模型 ID，不替换为嵌套的别名 ID。接口未提供地址的宿主账号渠道继续使用原生目录。

Host 通过 `llm.listConfigurableProviders()` 确认配置命名空间和路径，读取渠道的 `baseURL`、`apiKeyEnv` 与既有请求头，通过宿主 `credentials.resolve()` 解析密钥。浏览器只调用宿主鉴权 RPC，不能指定任意 URL，也不会收到密钥、请求头或完整原始响应。接口地址在已有 API 前缀后拼接 `/models`，根地址使用 `/v1/models`；禁止携带凭证跟随重定向。

按渠道规则，厂商取实时模型 ID 第一个斜杠前的前缀，例如 `agnes/agnes-3.0-flash` → `agnes`。DeepSeek 官方路线标记为 DeepSeek。没有前缀时可以使用有引用的联网资料或手动资料，不从显示别名猜测。

实时响应优先提供上下文、独立最大输入、最大输出、文本/图片/推理/工具/流式能力及明确的输入输出倍率。没有返回的字段依次参考手动资料、宿主配置与联网参考资料；仍缺失则保持未知。宿主解析出的上下文和输入类型也会保留，不再丢弃。价格字段不冒充倍率，上下文不减最大输出来推算输入。

推理能力和可选等级是两件事：接口可以声明支持推理，却没有提供具体等级，此时只展示 `default`。有明确且可映射到宿主的等级时才提供选择。选中接口新增、宿主尚未收录的模型时，Host 只补入对应的模型配置；显式等级尚不被宿主接受时同步该模型的等级映射。保存使用修订号校验，保留其他已有模型配置，再由原生 ModelDirectory 完成会话选模。

设置页「补充模型资料」保留为缺失字段的参考，实时响应中的字段优先。参考资料保存到插件自己的配置空间，不改变计费。只对实时目录中真实出现的模型执行选模准备，不根据显示名合并路线。

倍率相对于渠道自己的基准，并非最终价格，不可跨不同基准直接比价。手动资料仅作显示和筛选，不参与请求构造或计费。

## 联网补全模型资料

1. 在「模型助手 → 模型来源与联网资料」选择已配置的「资料整理模型」。默认关闭联网补全；关闭时刷新仍读取模型目录。
2. 确保宿主的联网搜索服务已配置并可用。插件调用 `ctx.web.search/fetch` 获取资料，再通过 `ctx.llm.prepareCall` 让所选模型提取字段。搜索能力由宿主提供，因此资料整理模型无需自带搜索接口。
3. 打开模型选择器，按需要选择渠道，点击「刷新模型列表与资料」。未筛选渠道时处理当前模型所在渠道；每次最多 6 个模型，优先当前模型，其余按最久未检索顺序处理，再次刷新可继续。普通打开、选模、工具读取和缓存读取不会触发联网研究。
4. 悬停模型查看引用与检索时间；在「补充模型资料」选择对应路线，可打开各字段的来源链接。

搜索与模型调用可能计费。检索使用模型 ID 和公开资料，不读取聊天记录。已知厂商优先限定官网域名；其他渠道使用公开搜索结果并标记为联网参考。每个字段须带实际检索结果中的 URL 与可匹配原文摘录，未知字段留空。模型输出仍可能误读资料，引用便于复核，不代表厂商担保。

联网资料仅支持上下文、最大输入/输出、文本/视觉/工具/推理/流式能力、厂商及知识截止日期。它不能添加可选模型、改写模型 ID、启用推理等级或生成价格倍率；真实目录与本地配置优先。资料和来源持久化在插件配置中，失败保留上次成功资料。模型目录仍只来自已配置的接口或宿主，不能凭网站介绍认定当前账号具有模型访问权限。

一次研究最多 6 次搜索、12 次页面获取和 1 次模型调用，整体预算 90 秒；模型响应有长度上限。引用只接受 HTTPS；搜索和抓取复用宿主的供应商选择、URL 限制与认证，模型整理阶段不获得工具权限。联网补全失败不会导致已经加载的目录失效。

## 开发与安装

```sh
npm ci
npm run build
npm run check
```

在 Harness 插件管理器添加本地插件时，使用本目录绝对路径。本地目录安装会链接该目录，请保留目录及依赖。普通使用可直接填写上述 GitHub 仓库地址。

打包文件包含 Host、Client、补丁、中文/英文展示资料及原创 SVG 图标，无安装脚本。运行依赖为 `@deepseek-ai/schemastery@3.18.5` 与 `@deepseek-ai/dsh-typert-protocol@0.2.1-rc.5`。模型目录仅向已配置的接口发出 GET 请求，每次限制 15 秒、8 MiB 响应；显式启用联网补全后，通过宿主搜索、抓取与 LLM 服务调用。日志仅记录渠道、数量、脱敏状态和耗时。

宿主同时提供 `model_assistant_catalog` 工具，复用与 UI 相同的读取和选模准备方法。工具返回经过字段白名单处理的资料；模型名等远端文本仍应作为外部数据看待。

配置写入复用宿主 `configForms` → `settings.mutate`，与宿主配置编辑工具使用同一条保存链路，携带命名空间版本与失败反馈。卸载清理注册、样式与订阅；关闭功能仅移除模型控件覆盖，保留设置页与用户配置。
